# DRIVECORE · Проверка

## Повторная проверка после исправлений безопасности

Сборка frontend/backend проходит. Обновлённый набор: **18/18 тестов**, без ошибок и пропусков. Проверены отзыв сессий после logout/смены пароля, CSRF (включая Unicode), некорректные UTC offsets, предел 72 байта bcrypt, CSV-формулы, раннее отклонение больших файлов и лишних multipart-полей, отсутствие остаточных файлов, журнал доступа и предупреждения администратора.

Локальные секреты заменены с подтверждения владельца. Старые файлы доступа удалены, `.env` имеет права 600. Проверка входа администратора дала 200; существующие приватные файлы запрещены Vite с 403. Для удалённых файлов браузер может получить SPA-страницу с 200; секретов в таких ответах нет.

В изолированном браузерном предпросмотре проверены вход → раздел «Безопасность» → отметка предупреждения → выход. Отметка сохраняется в PostgreSQL, ошибок консоли нет. Тестовые серверы остановлены. Эти проверки дополняют первоначальный полный путь ниже.

Для production создана отдельная Neon PostgreSQL и приватный Vercel Blob; миграции и seed новой базы выполнены успешно. Сайт опубликован: https://drivecore-puce.vercel.app; `/api/health` отвечает 200 и проверяет соединение с PostgreSQL. Сборка, регрессионные тесты и анализ CodeQL выполняются в GitHub Actions. Полный npm audit ещё ожидает разрешения на передачу метаданных зависимостей; CodeQL и Dependabot настроены в GitHub.

## Исправление отправки формы в облачной конфигурации

Форма сайта использует общий клиент `send`: при настроенном приватном хранилище поля передаются в JSON, а фотографии сначала загружаются по ограниченным разрешениям. При отправке с сайта источник всегда `website`, включая браузер со входом сотрудника. Добавлена регрессия: браузерный клиент получает cloud-конфигурацию и сохраняет FormData-заявку через настоящий API в отдельной тестовой PostgreSQL.

## Автоматические проверки

- `pnpm build`: TypeScript frontend/backend, Vite production build — успешно.
- Интеграционные тесты: 10 сценариев и родительский тест, 11/11 успешно, без пропусков.
- Авторизация, неверный пароль, роли администратора/менеджера/мастера.
- Публичная заявка: связанные клиент/автомобиль/услуга, источник website, уведомления, история действий.
- Серверная валидация обязательных полей, дат, отрицательного пробега/цен/оплаты, JSON и origin.
- Запись мастера и две конкурентные записи в одно время: одна успешна, другая получает 409.
- Заказ-наряд: работа 3500 + запчасть 8500 = 12000; частичная оплата 4000; остаток 8000. Две конкурентные оплаты остатка: принята только одна. Завершение с долгом отклоняется.
- Завершение, история клиента, аналитика и сохранение через новое соединение Prisma.
- Задачи: сохранение DONE и запрет изменения чужой задачи мастером.
- Файлы: multipart WebP, metadata в БД, сохранённые байты при скачивании, 401 без авторизации, поддельный MIME отклонён. Публичная форма с фотографией и текстовым именем услуги из примера ТЗ.
- Завершённый ремонт сохраняется в истории календаря.

Тестовый helper очищает только `drivecore_test`. Тестовые файлы пишутся в `.runtime/test-uploads`.

## Браузер

Проверен полный путь на тестовом предпросмотре 5174/4001: отправка формы → вход в CRM → контакт → назначение мастера и времени → работа → заказ-наряд → частичная/полная оплата → готовность → завершение → перезагрузка → история клиента. Значения и статусы сохранялись в PostgreSQL.

Дополнительно проверены:

- Настоящее перетаскивание заявки между колонками Kanban с подтверждением сохранения.
- Календарь день/неделя/месяц, переход периода и отображение записи.
- Глобальный поиск по госномеру и переходы к связанным сущностям.
- Центр уведомлений и отметка прочитанного.
- Справочники клиентов/автомобилей/сотрудников/услуг, заказы, финансы, аналитика и настройки — загрузка фактических данных без ошибок API.
- Задачи, сохранение комментария, загрузка WebP через диалог выбора файла.
- Клавиатурное переключение вкладок стрелками. Мобильное меню: Escape закрывает его и возвращает фокус; скрытая навигация недоступна для фокуса.
- Публичный сайт и основные экраны CRM на 375/768/1024/1440: ширина документа равна ширине viewport, таблицы и календарь прокручиваются внутри рабочей области.
- Production-сервер на временном порту 4002: реальные health/services/settings, маршрутизация CRM, вход, пустая рабочая база. В консоли сайта и проверенных экранов CRM нет ошибок.

Восьми фотографиям проведена визуальная проверка; все созданы специально для проекта и оптимизированы в WebP. Снимки браузера сохранены в `tests/artifacts/`, включая `preview.png`, `crm-empty.png`, `kanban.png`, `partial-payment.png`, `client-history.png`, `files-uploaded.png` и адаптивные размеры.
