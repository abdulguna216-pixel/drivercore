# DRIVECORE

Рабочий демонстрационный full-stack проект автосервиса: публичный сайт и CRM с общим Express API и PostgreSQL. Заявка с сайта сохраняет клиента, автомобиль, услугу и прикреплённые фотографии; автоматически появляется у сотрудников. Дальше доступны назначение времени и мастера, заказ-наряд, частичная оплата и история обслуживания.

## Уже подготовлено на этом компьютере

- Сайт: http://localhost:5173
- CRM: http://localhost:5173/crm
- API: http://localhost:4000/api/health
- Отдельный PostgreSQL 18: `127.0.0.1:55439`, база `drivecore`.
- Данные PostgreSQL: `.runtime/postgres`. Файлы клиентов: `backend/uploads`.
- Email администратора: `admin@drivecore.local`.
- Пароль администратора: `SEED_ADMIN_PASSWORD` в защищённом `.env` (права 600). Пароли остальных сотрудников задайте через CRM → Сотрудники. Файлы с копиями паролей не создаются; `.env` исключён из Git и запрещён для HTTP-раздачи.

Для повторного запуска на этом Mac откройте **`START.command`** двойным щелчком либо выполните `./START.command`. Он использует установленный PostgreSQL и доступный Node, выполняет миграции и идемпотентный seed. Если предпросмотр уже запущен, завершите его перед повторным запуском. Во время работы Codex серверы могут оставаться запущенными в его терминале.

## Стек и структура

React 19, TypeScript, Vite 6, Tailwind CSS, Lucide, dnd-kit; Node.js 22+, Express 4, Zod, Prisma 6, PostgreSQL 18; JWT в HttpOnly cookie, bcrypt.

```text
public-site/        Публичный сайт, форма записи и сгенерированные WebP
crm/                CRM: layouts, pages, components
frontend/src/       Общие компоненты, API-клиент, hooks, типы, стили
backend/src/        REST-маршруты, middleware, services, validation
backend/uploads/    Закрытое файловое хранилище
shared/             Статусы и подписи
database/prisma/    Prisma schema и версионированная SQL migration
database/seed.ts    1 администратор, 2 менеджера, 3 мастера, 6 услуг
scripts/            Совместный запуск и подготовка локальной базы
tests/              Интеграционные тесты реального PostgreSQL
docs/               Дизайн-система, visual direction, отчёт проверки
SPEC.md             Исходное ТЗ
```

UI UX Pro Max прочитан напрямую в GitHub без установки по просьбе пользователя. Дизайн-система составлена по его статическим инструкциям и ТЗ; локальный поисковый скрипт `--design-system` не запускался. Все 8 фотографий созданы встроенным генератором специально для DRIVECORE, оптимизированы в WebP и сохранены в `public-site/assets`. Сторонних стоков и внешних зависимостей для загрузки изображений нет.

## Запуск на другом компьютере

Требуются Node.js 22+, pnpm 11 и PostgreSQL 15+ с доступной extension `btree_gist`. Для Docker вариант ниже.

```bash
pnpm install
cp .env.example .env
```

Настройте `DATABASE_URL`, `JWT_SECRET` (минимум 32 случайных символа), `SEED_ADMIN_EMAIL` и `SEED_ADMIN_PASSWORD` (минимум 12 символов). Пример создания базы существующим администратором PostgreSQL:

```sql
CREATE USER drivecore WITH PASSWORD 'ваш_случайный_пароль';
CREATE DATABASE drivecore OWNER drivecore;
```

Миграция создаёт `btree_gist`, все таблицы и ограничение пересечения записей мастера. При ограниченных правах попросите администратора базы создать extension заранее.

```bash
pnpm db:generate
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Frontend: `5173`, backend: `4000`. Vite проксирует `/api` в backend. Для раздельного запуска: `pnpm dev:api` и `pnpm dev:web` в двух терминалах. Для новых изменений схемы: `pnpm exec prisma migrate dev --schema database/prisma/schema.prisma --name имя_изменения`.

Seed не создаёт заявки, клиентов и финансовые показатели. Повторный seed сохраняет существующих пользователей, пароли и данные. Для дополнительных сотрудников создаются случайные пароли без сохранения открытых копий. Администратор задаёт им новые пароли в CRM. Пароли должны содержать минимум 12 символов и занимать не больше 72 байт UTF-8.

### Локальная база внутри проекта

`pnpm setup:local` автоматически создаёт `.env`, секреты и отдельный кластер PostgreSQL, если их ещё нет. На Mac обнаруживает `/Library/PostgreSQL/18/bin`; в другом окружении задайте `PG_BIN=/путь/к/bin/PostgreSQL`. Порт по умолчанию `55439`; при необходимости поменяйте его в `DATABASE_URL` до запуска. Этот сценарий предназначен для отдельной локальной базы `drivecore`, не для существующей удалённой базы.

Остановка локального PostgreSQL на этом Mac:

```bash
/Library/PostgreSQL/18/bin/pg_ctl -D .runtime/postgres stop -m fast
```

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Подключение Prisma к PostgreSQL |
| `JWT_SECRET` | Секрет подписания JWT |
| `SEED_ADMIN_EMAIL` | Email первого администратора |
| `SEED_ADMIN_PASSWORD` | Пароль только для первого создания администратора |
| `APP_ORIGIN` | Разрешённые origin через запятую |
| `PORT`, `HOST` | Порт и адрес backend (локально 4000 / 127.0.0.1) |
| `UPLOAD_DIR` | Папка для вложений |
| `NODE_ENV` | В production cookie всегда Secure; требуется HTTPS |
| `TRUST_PROXY` | `1` только за доверенным прокси; локально `0` |
| `UPLOAD_MAX_BYTES` | Общая квота файлов, по умолчанию 1 ГиБ |
| `BLOB_READ_WRITE_TOKEN` | Только серверный токен приватного Vercel Blob |
| `CRON_SECRET` | Секрет авторизации ежедневной очистки Vercel |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Необязательные уведомления о новых заявках |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL при Docker-запуске |
| `DOCKER_APP_ORIGIN` | Origin сайта в Docker (по умолчанию localhost:8080) |

Все записи и отображаемое время сервиса используют Москву, UTC+3; системный часовой пояс браузера не изменяет время записи. Даты на сайте вводятся как календарные даты.

## Docker

Задайте в `.env` `POSTGRES_PASSWORD` (случайный URL-safe пароль), `JWT_SECRET`, `SEED_ADMIN_PASSWORD`; затем:

```bash
docker compose up --build -d
```

Сайт и CRM: http://localhost:8080. В compose три сервиса: PostgreSQL, backend, frontend/Nginx. PostgreSQL и API доступны только внутри сети compose. Данные БД и вложения хранятся в named volumes. Миграции и seed выполняются при старте backend. Для внешнего размещения используйте HTTPS, `DOCKER_NODE_ENV=production` и фактический origin. Nginx передаёт адрес непосредственного клиента. Compose подготовлен, но на текущем компьютере Docker отсутствует, поэтому контейнерный запуск не проверен.

## Production build

```bash
pnpm build
pnpm start
```

Express отдаёт собранный `dist` и API на одном адресе; CRM открывается по `/crm`. Backend компилируется в `dist-server`. Задайте `NODE_ENV=production`, корректный HTTPS `APP_ORIGIN`. Для размещения вне локального компьютера задайте `HOST=0.0.0.0`.

На Vercel `api/index.js` обслуживает Express, а Vite публикует `dist`. Требуются PostgreSQL и **приватный** Vercel Blob. Задайте в production `DATABASE_URL`, `JWT_SECRET`, `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `APP_ORIGIN`, `TRUST_PROXY=1`, `BLOB_READ_WRITE_TOKEN` и `CRON_SECRET`. Перед первым развёртыванием выполните миграции и seed с переменными новой базы; не используйте удалённую базу для тестов. Клиент загружает файлы напрямую в Blob по ограниченному одноразовому разрешению; API проверяет заголовок, размер, владельца и связь с заявкой. Скачивание выполняется только через авторизованный API. Ежедневный защищённый Cron удаляет просроченные загрузки и сессии.

Исходники: [abdulguna216-pixel/drivercore](https://github.com/abdulguna216-pixel/drivercore). Подробные локальные отчёты безопасности не публикуются в репозитории.

## Возможности

- Полная форма записи с фотографиями и серверной валидацией; создание связанных записей транзакцией.
- JWT/HttpOnly cookie, bcrypt, серверные сессии и их отзыв при выходе или изменении доступа, роли ADMIN/MANAGER/MECHANIC, проверка активности и роли пользователя на каждом запросе. Подписанный CSRF-токен обязателен для изменений.
- Обзор с фактическими данными, график недели и сегодняшние записи.
- Kanban с drag-and-drop; альтернативное изменение статуса через select; список, поиск, 6 фильтров, пагинация, обновление каждые 5 секунд и при возвращении во вкладку.
- Карточка заявки: информация, клиент, автомобиль, задачи, комментарии, файлы, история, финансы.
- Каталог клиентов и автомобилей, создание и редактирование, VIN и история ремонта.
- Календарь день/неделя/месяц, назначение/перенос записи, фильтр по мастеру. Проверка конфликтов в транзакции + exclusion constraint PostgreSQL защищают от одновременных запросов.
- Заказ-наряды: работы/запчасти, количество/цена, расчёт Decimal на сервере, печать.
- Частичная/полная оплата, методы CASH/CARD/TRANSFER, остаток и история. Блокировка строки заказа не допускает конкурентную переплату; после оплаты состав заказа фиксируется. Завершение возможно после заполнения заказа и погашения остатка.
- Мастер видит назначенные заявки и автомобили, может начать работу, отметить готовность, комментировать и добавлять работы; не управляет оплатами, клиентами и настройками.
- Управление сотрудниками/услугами администратором, настройки контактов сайта.
- Центр уведомлений, глобальный поиск, аналитика с выбором периода и CSV.
- Вложения до 5 файлов по 20 МБ для сотрудников; публичная форма принимает только JPG/PNG/WebP до 5 МБ. Локально файлы находятся на диске, на Vercel — в приватном Blob; скачивание защищено авторизацией и правами на заявку. Ограничены multipart-поля, части, размер тела и общий объём хранилища.
- Административный журнал безопасности и предупреждения о повторных отказах доступа, подборе паролей, изменениях прав, ошибках сервера и заполнении хранилища. Пароли, токены и содержимое форм в журнал не записываются.
- Подготовлена необязательная Telegram-интеграция. Без токена никаких внешних отправок нет. Ошибка Telegram не отменяет сохранение заявки.

## REST API

Публичные: `GET /api/services`, `GET /api/settings`, `GET /api/auth/csrf`, `POST /api/requests`, `POST /api/auth/login`. `/api/health` проверяет реальное подключение БД. Перед изменяющим запросом получите `/api/auth/csrf`, сохраните cookie и передайте `token` в заголовке `X-CSRF-Token`; встроенный клиент делает это автоматически.

`POST /api/requests` принимает JSON либо multipart/form-data с полями формы и `files`. Услуга — `serviceId`, также поддерживается `service` с именем каталога и примером «Замена тормозных колодок». У публичных заявок `source` всегда `website`, даже если клиент пытается отправить другой источник. Анонимный ответ содержит номер, без клиентских данных.

Остальные маршруты требуют cookie с JWT:

```text
GET/POST       /api/requests
GET/PATCH/DELETE /api/requests/:id
POST           /api/requests/:id/comments
POST           /api/requests/:id/tasks
POST           /api/requests/:id/files
PATCH          /api/tasks/:id
GET            /api/files/:id/download
GET/POST       /api/clients, /api/cars, /api/appointments, /api/work-orders
GET/PATCH      /api/clients/:id, /api/cars/:id
PATCH          /api/appointments/:id
GET            /api/work-orders/:id
PUT            /api/work-orders/:id/items
GET/POST       /api/payments
GET/POST/PATCH /api/users, /api/services (PATCH с /:id)
PATCH          /api/settings
GET            /api/dashboard, /api/analytics, /api/search, /api/notifications
PATCH          /api/notifications/read
POST           /api/auth/logout
GET            /api/auth/me
GET            /api/security (только ADMIN)
PATCH          /api/security/alerts/:id (только ADMIN)
GET            /api/uploads/config
POST           /api/uploads/tickets, /api/uploads/tickets/:id/complete
```

Удаление заявки разрешено только администратору и до создания заказ-наряда. Для заказов с финансовой историей предусмотрена отмена статусом. Заявки/клиенты/автомобили/заказы/оплаты поддерживают `page`, `limit` (до 100). Фильтры заявок: `q,status,source,managerId,mechanicId,serviceId,date`. Аналитика: `days=7|30|90|365`. Поиск: `q` от двух символов.

## Проверка

```bash
pnpm typecheck
pnpm test
pnpm build
```

Тесты используют отдельную базу **`drivecore_test`** на том же PostgreSQL. Они создают её и очищают только её таблицы перед запуском. Рабочая `drivecore` не очищается. Пользователь подключения должен иметь право создать тестовую базу либо база должна уже существовать. Тестовые вложения — `.runtime/test-uploads`.

Интеграционный сценарий проверяет авторизацию, роли, публичную заявку, валидацию, календарь и конкурентные записи, заказ-наряд, частичную оплату и конкурентную переплату, завершение, историю и сохранение через новое подключение к БД. Дополнительные проверки: задачи, файлы, служебные изменения и недопустимые origin.

Браузерная проверка выполнена в отдельном тестовом предпросмотре (5174/4001), чтобы оставить рабочую CRM без тестовых заявок. Проверены реальная отправка формы, вход, обработка, запись мастеру, состав заказа, частичная/полная оплата, завершение, перезагрузка и история клиента. Снимки: `tests/artifacts`; отчёт: `docs/VERIFICATION.md`.

Контактные данные и маркетинговые показатели в публичном тексте — демонстрационные данные из ТЗ. Цены — базовая стоимость работ, не публичная оферта. Для реального сервиса замените контакты через настройки CRM и тексты в `public-site/PublicSite.tsx`.
