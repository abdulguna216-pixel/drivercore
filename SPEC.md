# ЗАДАЧА

Создай полноценный веб-проект, состоящий из двух связанных частей:

1. **Публичный сайт автосервиса**
2. **Внутренняя CRM-система для сотрудников**

Главная задача проекта — реализовать реальную связку:

**Сайт → заявка клиента → backend/API → база данных → CRM → обработка заявки → заказ-наряд → завершение работы**

Это должен быть не просто визуальный макет, а рабочий full-stack проект с сохранением данных в базе.

Проект создаётся как демонстрационный, поэтому интерфейс должен выглядеть современно, профессионально и правдоподобно, как коммерческий продукт.

---

# 1. КОНЦЕПЦИЯ

Название автосервиса:

**DRIVECORE**

Направление:

- техническое обслуживание автомобилей;
- диагностика;
- ремонт;
- шиномонтаж;
- тормозная система;
- подвеска;
- замена технических жидкостей;
- компьютерная диагностика;
- электрика.

Основная задача публичного сайта:

**получить заявку на обслуживание автомобиля.**

Основная задача CRM:

**позволить сотрудникам автосервиса обработать заявку от момента поступления до завершения ремонта и оплаты.**

## ACCESSIBILITY

Обязательно учитывать рекомендации UI UX Pro Max по accessibility.

Минимальные требования:

- достаточный контраст текста;
- видимые focus states;
- полноценная клавиатурная навигация;
- корректные semantic HTML elements;
- label для input;
- accessible name для icon buttons;
- не передавать статус только цветом;
- учитывать `prefers-reduced-motion`;
- интерфейс не должен ломаться при увеличении текста;
- длинный текст, номера, VIN и комментарии не должны обрезаться без возможности увидеть полное значение.

## ПРАВИЛО ДВИЖЕНИЯ

Анимации должны усиливать интерфейс, а не превращать сайт в демо эффектов.

Приоритет:

```text
clarity
performance
smoothness
usability
brand consistency
```

Избегать:

```text
эффектов ради эффектов
слишком долгих анимаций
резких zoom
хаотичных 3D-вращений
постоянно движущихся элементов
анимаций, мешающих чтению
тяжёлых эффектов, снижающих FPS
```

Все анимации должны учитывать:

```css
prefers-reduced-motion
```

На мобильных устройствах тяжёлые эффекты необходимо упрощать или отключать.

# 3C. ВСЕ ВИЗУАЛЫ ГЕНЕРИРОВАТЬ САМОСТОЯТЕЛЬНО

**Критически важное требование: все визуальные материалы для сайта создавать самостоятельно с помощью генерации изображений.**

Не использовать случайные фотографии из:

```text
Unsplash
Pexels
Shutterstock
Freepik
Google Images
stock photo libraries
```

Не использовать изображения с чужих сайтов.

Не использовать готовые стоковые фотографии сервиса как основной визуальный контент.

Каждый ключевой визуал должен быть создан специально под DRIVECORE и соответствовать единому арт-дирекшену проекта.

---

## ВИЗУАЛЬНАЯ КОНСИСТЕНТНОСТЬ

Все изображения должны ощущаться как одна фотосерия, снятая в одном реальном автосервисе.

Сохранять одинаковые:

- характер освещения;
- температуру света;
- контраст;
- зерно;
- обработку;
- уровень реализма;
- материалы интерьера;
- форму сотрудников;
- цвет оборудования;
- характер помещения;
- акцентный цвет бренда.

Не должно возникать ощущения, что фотографии собраны из разных фотобанков.

---

## ФОТОГРАФИИ АВТОСЕРВИСА

Фотографии сервиса должны выглядеть **как реальные кадры, снятые между делом во время рабочего дня**, а не как рекламная фотосессия.

Требования:

- естественная композиция;
- допускается небольшая визуальная неряшливость;
- кадр не обязан быть идеально симметричным;
- автомобили могут быть частично перекрыты оборудованием;
- инструмент может лежать на рабочей поверхности;
- на полу допустимы естественные следы эксплуатации;
- помещение должно выглядеть рабочим и используемым;
- механики заняты реальной работой;
- люди не позируют;
- никто специально не смотрит в камеру;
- никаких постановочных рукопожатий;
- никаких групп сотрудников, улыбающихся в объектив;
- никаких идеально выстроенных машин;
- никаких стерильных помещений, похожих на шоурум.

---

## ЧЕГО НЕ ДОЛЖНО БЫТЬ В ФОТО

Запрещены типичные признаки стоковой рекламы:

```text
идеальная симметрия
стерильно чистый пол
идеально выстроенные автомобили
позирующие механики
улыбки прямо в камеру
рукопожатия
палец вверх
команда сотрудников в ряд
пустой сервис без следов работы
чрезмерно глянцевые автомобили
неестественно идеальный свет
корпоративная постановочная фотография
```

Фотография должна создавать ощущение:

**«этот кадр реально сняли внутри работающего сервиса»**.

---

## ОДИН АКЦЕНТНЫЙ ЦВЕТ

Во всей серии визуалов должен использоваться **один и тот же акцентный цвет**, совпадающий с основным accent color интерфейса.

Для текущей дизайн-системы базовый ориентир:

```text
#FF5A1F
```

Но если UI UX Pro Max обоснованно предложит другой основной accent color, использовать именно итоговый цвет дизайн-системы.

Акцентный цвет должен повторяться естественно и ненавязчиво:

- элементы формы механиков;
- полосы на оборудовании;
- инструментальные тележки;
- детали подъёмников;
- небольшие элементы интерьера;
- световые элементы;
- перчатки;
- маркировка рабочих зон.

Не окрашивать всё изображение в акцентный цвет.

Цвет должен быть связующим визуальным мотивом, а не цветовым фильтром поверх фотографии.


## ЛОГОТИПЫ И БРЕНДИНГ ВНУТРИ ФОТО

Не вставлять случайные или вымышленные логотипы производителей на стены, одежду или оборудование, если они не нужны сцене.

Не генерировать искажённые автомобильные логотипы крупным планом.

Фирменный брендинг DRIVECORE внутри фото использовать только там, где он действительно нужен, и лучше реализовывать его средствами интерфейса или отдельными контролируемыми графическими слоями.

## НАБОР ВИЗУАЛОВ ДЛЯ ПУБЛИЧНОГО САЙТА

Сгенерировать как минимум следующие визуалы:

### 1. HERO

Современный автомобиль на подъёмнике или в рабочей зоне сервиса.

Не центральная идеально симметричная композиция.

В кадре видны реальные признаки работы.

Оставить удобную негативную область под HTML-заголовок и CTA.

---

### 2. ДИАГНОСТИКА

Механик работает с автомобилем и диагностическим оборудованием.

Снимать сбоку или через детали интерьера.

Не смотреть в камеру.

---

### 3. ТОРМОЗНАЯ СИСТЕМА

Реальный рабочий кадр ремонта тормозного узла.

Инструмент и детали выглядят используемыми.

---

### 4. ПОДВЕСКА

Автомобиль на подъёмнике.

Механик работает снизу.

Кадр не постановочный.

---

### 5. ТЕХНИЧЕСКОЕ ОБСЛУЖИВАНИЕ

Замена масла или работа под капотом.

Реальные рабочие детали.

---

### 6. ШИНОМОНТАЖ

Рабочая зона шиномонтажа во время процесса.

---

### 7. ИНТЕРЬЕР СЕРВИСА

Широкий живой кадр помещения.

На фоне могут быть сотрудники, автомобили, оборудование.

Никто не позирует.

---

### 8. ДЕТАЛЬНЫЕ КАДРЫ

Дополнительно можно создать несколько close-up:

- инструменты;
- тормозной диск;
- колесо;
- двигатель;
- диагностическое оборудование;
- рабочие перчатки;
- детали подвески.

Они должны сохранять тот же art direction.

# 66. ФИНАЛЬНЫЙ РЕЗУЛЬТАТ

В результате должен получиться законченный демонстрационный продукт:

```text
DRIVECORE
```

с публичным сайтом автосервиса и внутренней CRM.

Клиент оставляет заявку на сайте.

Заявка автоматически появляется в CRM.

Менеджер обрабатывает её.

Назначает дату и мастера.

Проект должен выглядеть и работать так, чтобы его можно было использовать как полноценный проект для портфолио и демонстрации связки:

**Frontend + Backend + API + PostgreSQL + CRM.**
